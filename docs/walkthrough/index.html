voxren-pi · how one session works

Voxren Coach Walkthrough

You type coach. Eight steps later a League coach answers in your terminal. Each step has a plain version first, then the deeper details for when you want them.

01You run coach

Plain version

Node runs bin/coach.mjs. It gathers your settings and keys, sets up a private folder, then starts Pi, the AI agent framework, with the coach plugged in. Node waits until Pi exits.

Deeper
  • Keys load in a fixed order: environment first, then the .env file. Perplexity, TypeSafe and Gemini keys fall back to the OS key store (macOS Keychain or Windows DPAPI), read through a helper child process with a 3 s timeout, so a locked Keychain never hangs launch.
  • An allowlist (FORWARDED_ENV) decides which variables reach Pi. Everything else in your environment stays out.
  • Pi gets its own HOME under the coach home (~/Library/Application Support/voxren-coach on macOS), so your personal Pi config never leaks in.
  • Launch flags strip Pi down: --no-extensions --extension src/index.ts --no-builtin-tools --no-skills. The coach is the only plugin, and Pi's coding tools are off.

02Pi loads the coach extension

Plain version

Pi is generic. src/index.ts turns it into a League coach: it adds 8 tools, the slash commands, a header and a footer, and listens for events like "a turn is starting" or "a tool just finished".

Deeper
  • session_start: starts the League client poller (every 5 s, every 2 s in champ select) and warms up the research service.
  • before_agent_start: starts a turn timer (180 s default), routes the model, and adds your learnings summary to the prompt.
  • tool_call: blocks any tool not on the exact list. model_select: picking a model that isn't approved aborts and shuts the session down.
  • user_bash: shell commands are always denied. It's a coach, not a coding agent.

03The router picks a model

Plain version

Easy questions go to a fast model. Hard ones get a stronger model that thinks longer. A judge called Jev grades each prompt as quick, standard or deep, and code (never the prompt) makes the final call.

Deeper
  • Only the first 4,000 characters of a prompt go to Jev, and your Riot IDs are scrubbed out first.
  • The 1.5 s deadline races a plain setTimeout, never an unref'd timer. On Windows, Bun never fires a lone unref'd timer, so the race would hang (rule 8 in AGENTS.md).
  • The route shows as a row in the chat. The context event strips that row from every request, so the model never sees it.

04Commands and tools

Plain version

A slash command is a ready-made question with a fixed tier. Tools are what the model can reach for while answering: search, game data, your match history.

CommandTierWhat it does
/reviewdeepAudit your last ranked games and name the top 3 habits to fix
/otpdeepRead a one-trick's recent games and lay out the build to copy
/matchupstandardLane plan for a matchup
/buildstandardBuild, runes and skill order for this patch
/patchstandardWhat changed this patch, and whether it changes how you play
/compstandardRead the current draft or game and get a strategy call
/draftquickYour call for the current draft, in four short rows
/pickquickThe pick call for your hovered or locked champion
/config, /riot-keynoneSettings panel and Riot key setup, with no model call

Tools: web_search, voxren_game_facts, voxren_meta_research, voxren_strategy_frame, voxren_player_audit, voxren_otp_build, voxren_remember, voxren_video_research.

Deeper
  • Commands read the League client only when they run. src/lcu.ts finds the client's lockfile, then makes HTTPS calls to 127.0.0.1 that are pinned to Riot's root certificate in data/riotgames.pem.
  • Auto calls, on by default and off with VOXREN_COACH_AUTO_COMP=0: /pick fires when your champion is locked or has stayed hovered for two polls, and /draft when you and four enemies have locked in. Together they fire at most 5 times per champ select, and only while the coach is idle.
  • Every prompt and tool description lives in coach.yaml. No prompt text is allowed in a .ts file.

05One turn, start to answer

Plain version

The model asks tools for evidence and reads what comes back, then answers. Jev checks the sources on the way in and the claims on the way out.

Deeper
  • The passage screen (src/passage-judge.ts) scores web results, video transcripts and OP.GG summaries before the model sees them.
  • Grounding (src/grounding-judge.ts) sits behind voxren_strategy_frame. It checks each claim against the cited passage text. It flags unsupported claims and never deletes them.
  • src/policy.ts caps sizes: 12 KB per gateway payload, 8 KB of display text, 64 KB per chart. Bad input fails with a typed SafeToolError, and terminal escape codes are stripped.
  • Side jobs that need a model, like summarizing a video, run in a worker: a second, bare Pi run for one prompt, with no coach tools and no session.

06Matchup notes build themselves

Plain version

The first time you look up a matchup, the coach starts writing a study note on it in the background. The next time, the note is ready.

Deeper
  • Notes are saved one file per matchup: <coach home>/matchups/<champion>-<opponent>.json.
  • The build collects videos and guides through the Python research service, then a worker distills and merges them. A row is kept only when the Jev grounding judge finds it in its source.
  • voxren_meta_research returns a finished note next to the OP.GG rows, under its own guide-N evidence id.

07The screen

Plain version

Answers arrive as cards. Each block has a coloured bar and a short upper-case label. A call that's still running shows a spinner and a clock.

Deeper
  • src/ui.ts handles presentation only. src/terminal-images.ts is the one file allowed to draw pictures. It rasterizes SVG charts with resvg and draws them with the Kitty or iTerm2 image protocol. Sixel is opt-in.
  • A terminal that can't draw images gets block-character text strips. Warp on Windows is forced to text because it reserves blank rows for images it never draws.

08After each turn

Plain version

Each turn is logged. When the coach audits your games, it remembers your habits and brings them up next time.

Deeper
  • Each turn appends one NDJSON line to <coach home>/exchanges.ndjson: the prompt, every tool call with timing, the answer, tokens and cost. The lab scripts read this file.
  • After a successful voxren_player_audit, results are folded into a learnings file for your account, for example deaths before minute 6 or being ahead at 15 and then dying. A summary of up to 400 characters goes into the next prompt. You can turn this off in /config.
  • session_shutdown stops the pollers and closes the gateway, including the research service it started.

··Which file does what

··Words to know

Pi
The agent framework the coach runs inside. It handles the chat, sessions and model calls.
Jev
TypeSafe System One, a judge model. It grades prompts, screens sources and grounds claims. It's on only when TYPESAFE_API_KEY is set.
Grounding
Checking that a claim actually appears in the source it cites.
Route
The model and thinking level chosen for one turn. You see it on screen, and the model never does.
Worker
A second, bare Pi run for one side job. It has no coach tools and no session.
LCU
League Client Update, the local HTTPS API the League client exposes on your machine.
MCP
Model Context Protocol. OP.GG runs a public MCP server that the gateway calls for meta and matchup stats.
Data Dragon
Riot's static data for champions, items and versions. Game facts come from here, never from constants in code.
